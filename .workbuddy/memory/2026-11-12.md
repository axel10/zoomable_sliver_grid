## 上述漂移已修（同日）

**先纠正定性**：与段数无关，只与位置有关。四场景探针（改前）：
3 段中段 px=1781 → 0.00；3 段顶部一屏内 px=868 → −4.8/轮；2 段同位置 → −4.8/轮；
1 段同位置 → **+34.9/轮**。所以早就有这个问题，只是既有测试都在中段或 `px == 0` 跑。

**根因**：`_resolveFocusY` 的 topBlend 让焦点高度 `f` 依赖 `pageTop`，而 `pageTop` 随档位变
（实测 gx6 settle `f=400.0`、gx8 settle `f=375.9`）。换档 target 用**冻结的** f 解：
`px = pageStart + geom.offset + r*stride - f_old`；settle 后 `_recomputeAnchor` 却用**新算的**
f 反取内容点 → 同一像素被解释成另一个内容点，偏差 `f_new - f_old`，往返一次永久丢掉，反复换档
持续漂。只要「解目标」和「反取内容点」用同一个 f，两档换算就可逆。

**修复**（`lib/src/zoom_layout_utils.dart`，+65 行）：
- 新增 `_frozenFocusFrame` / `_frozenFocusY`：过渡结束那一帧把冻结的 `anchorFocusY` 抄下来，
  本帧内所有 `record` 调用都用它反取锚点；下一帧恢复正常重算（无害，因为下次换档的 target
  也用同一帧记录的值）。
- `_recomputeAnchor` 增加可选参数 `frozenFocus`；只在 `_anchorEdge == none` 且锚段未变时生效，
  贴顶 / 贴底仍走原有的精确对齐判定。
- **关键坑**：第一版用 `reuseFrozenFocus: _wasMixing` 布尔量，结果与修复前逐位相同（847.366109785203）。
  原因是**一帧内每个参与布局的 sliver 各调一次 `record`**，第一次就把 `_wasMixing` 清掉，
  后两次调用用新 f 把复用的值覆盖回去。必须按帧号冻结。

**验证**：四场景 worstDrift 全部 0.00（含贴底场景）。
`test/zoom_multi_section_n_test.dart` 现有 8 条用例（3/4 段 × 焦点不跑段、段间间距、往返不漂、
渐变区往返不漂）。最后一类在关掉修复时会红（漂 22px），可作有效性自检。全套 96 条通过。

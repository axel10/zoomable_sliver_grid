## zoomable_sliver_grid 换档滚动锚定：改为焦点锚定（0.0.1 → 0.0.2）

**问题诊断（已确认）**
- `Scrollable.maybeOf(context)` 在 `FolderZoomSliverBuilder` 的 context 上恒为 `null`
  （builder 在 `CustomScrollView` 之上，maybeOf 只查祖先）→ 滚动补偿从未执行，
  顶部因为 offset=0 恰好正常，中段/底部换档纯跳变。
- tracker 只处理顶边界（`viewportTop <= 0`），没有底边界；`viewportTopForLayer` 只有下界夹取，
  真被 `maxScrollExtent` 夹住时假想视口与真实视口差 2800+ px → 可见性判断全错 → 整屏空白帧。
- 过渡期"单侧可见"条目走 `scrollOffset + delta` 钉住写法，叠加上述问题 = 画面冻住再整屏跳。

**方案（用户已确认）**
- 不变量改成"焦点处的内容不动"：`c = vTop + f; i, r = indexAt(c), (c-oA(i))/strideA;
  targetTop = oB(i) + r*strideB - f`。与顶部锚定只差 `r*(strideB-strideA)`。
- `r` 用**槽位步距**（条目高度+行间距）为分母，否则焦点落在行间空隙时被压到 1.0，凭空多/少一行。
- 焦点：默认视口中心；捏合取双指中点；距顶/底不足一屏时把 f 渐变到 0/视口底（两端退化顶/底对齐）。
- 贴边（±0.5px）直接记成 top/bottom 锚；底部用两端内容总高之差平移，避开 SliverPadding 的坐标偏差。
- 过渡期把 `correction = 真实vTop - 假想vTop`（按层权重）加到各层视口顶部，可见性判断与屏幕一致。
- 滚动与布局共用同一个 eased 值，多档跳转直接从起点解到终点，不做逐档累加。

**落地**
- `FolderZoomSliverBuilder` 新增可选 `controller`；未传时用 `RenderViewportBase.offset` 从渲染树自动发现。
- `FolderZoomViewportTracker` 重写（焦点锚 + 边界 + contentCount + spacings + correction）。
- `_SliverAnimatedZoomGridLayout.contentExtentIn` 由 `_maxScrollOffsetIn` 抽出为静态；`computeMaxScrollOffset` 回填 childCount。
- pinch：`FolderZoomPinchController.focalGlobal`，手势层传双指中点，捏合开始时 `refreshAnchor`。
- 新增 `test/zoom_anchor_test.dart`（10 条：顶/中/底 × 双向、贴底精度、空白帧、无 controller 兜底、捏合）。
- 顺手修了 `example/test/widget_test.dart` 引用不存在的 `MyApp`；README/CHANGELOG 补焦点锚说明。

**验证**：`flutter analyze` 干净；`flutter test` 10 passed；example 冒烟测试通过。

## 触底换档「条目从下往上弹一下」（0.0.2 → 0.0.3）

用户报：滚到底部再放大档位，几乎所有条目快速从下往上弹一下。用逐帧探针（记录每条目
`tester.getRect().top`）实测出四个独立成因，都在 `lib/src/zoom_layout_utils.dart`：

1. **几何按布尔可见性分支**（主因）：`getGeometryForChildIndex` 里"两层都可见→加权混合，
   只有一层可见→`geom.scrollOffset + (viewportTop - layerViewTop)` 锁死到该层屏幕位置"。
   过渡期滚动要平移几千像素，条目会反复翻转可见性，每翻一次就在混合值与层锁定值之间瞬移。
   探针实测 item 107 逐帧 `51 → -18 → 280 → 527 → 366`、item 112 `-240 → 156 → -259`。
   改为**纯几何加权**：`paintTop = Σw·(o_L - layerTop_L) - correction`，对 progress 连续。
2. **`_onTick` 用上一帧的 `maxScrollExtent` 夹取**插值位置。触底换档内容每帧长上千像素，
   滚动永远慢一帧 → 条目被画低上千像素再被拽回。删掉夹取，越界交给
   `applyContentDimensions`（`jumpTo` 越界不会被立即夹取，会走回弹模拟，很丑，别再依赖它）。
3. **终帧补偿丢失**：`AnimationController` 最后一 tick 先 `stop()` 再 `notifyListeners()`，
   `isAnimating` 已 false。改成 `addStatusListener` 在 `completed` 里补最后一帧
   （原来触底会停在离底部 ~13px，且残差随帧率变化）。
4. **过渡中再次换档目标算高**：`_startSliverOffset` 取 tracker 里上次布局的 `viewportTop`，
   `_startScrollPixels` 取当前 `position.pixels`，差一整帧。新增
   `FolderZoomViewportTracker.pixelsAtLayout` + `scrollPixelsReader` 回调（build 期由
   state 注入 `_scrollPosition()?.pixels`），用 `_sliverTopForPixels()` 对齐到同一时刻。
   连点两档曾多算 290px。pinch 路径同样改用该 helper。

**连带删除**：单侧可见条目的原地淡入淡出（`resolveItemTransition` 现恒返回 `isShared: true`）。
`kFolderZoomFadeScaleDelta` 标 `@Deprecated`，`isGeometryVisibleInViewport` 已删。
`zoom_item_scaffold.dart` 里 `isFadeScale` 分支保留为死路径未动。

**新增回归测试** `test/zoom_transition_motion_test.dart`：断言过渡期每个条目屏幕位置**单调**
（不允许中途折返，方向按自身净位移判定——触底时方向取决于内容总高变大还是变小，与放大缩小无关）。
覆盖竖屏/横屏触底放大、触底缩小、中段、连点两档。`flutter test` 15 passed，analyze 干净。

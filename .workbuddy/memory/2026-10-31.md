# 2026-10-31

## 安卓真机「捏合放大时所有条目都位移」：捏合路径缺 itemPinning

**现象**：双指捏合（0.333 → 0.500，列表小 → 列表大）时整屏条目一起上下漂；
点档位面板直接换档则只有共同可见条目位移、单侧条目原地淡入淡出。

**根因**（`lib/src/zoom_layout_utils.dart`）：`build()` 里有两条换档路径。
- 点击换档走 `_applyTargets(animate: true)`，里面调 `tracker.buildPinning(...)` 冻结
  "单侧可见条目"处置表，再作为 `metrics.itemPinning` 传下去 → 行为正确。
- 捏合换档走 `build()` 的 `pinch.isActive` 分支，`FolderZoomLayoutMetrics` **根本没传
  `itemPinning`（也没传 `transitionProgress`）** → `pinning == null` →
  `getGeometryForChildIndex` 全部走"各层加权平均"，于是每个条目都在两层几何之间插值位移。
  日志里 `[zoom][layout] mix ... layers=lx2/w0.49/e80.0,lx2/w0.51/e56.0` 每帧都在变，
  正是全体条目在动。

**修法**：新增 `_pinchPinning / _pinchPinningFrom / _pinchPinningTo / _pinchPinningReady`
+ `_resolvePinchPinning()`，在捏合分支里传入 `itemPinning` 与 `transitionProgress: t`。
- 缓存 key = (起始档位, 目标档位)；方向未定时返回 null。
- `mixLayers` 用 `_effectiveGeometryLayers(_curved.value)`（从点击动画中途接管时参照系正确）。
- `targetViewportTop` 用 `viewportTopForLayer(targetLayer)` 而非 `solveViewportTopFor`，
  与布局侧 `_layerViewportTop` 同口径，淡入条目在 `progress = 0` 处锁定值 == 目标值，起步不跳。
- 目标中途反转（双指间距跨过手势起点）时按新 key 重算：反转只可能发生在 `progress ≈ 0`，
  此时两层权重 (1, 0)，重算等价于按起始档位重新判定，不会瞬移。
- `_onPinchChanged` 里 `!pinch.isActive` 时 `_resetPinchPinning()`。

**测试**：新增 `test/zoom_pinch_single_side_fade_test.dart`，用真实双指手势驱动
`ZoomGestureLayer`（400×800、顶部 px=0），断言捏合中单侧条目原地不动（< 1.5px）且透明度变化、
共同可见条目仍位移。已验证：把 `itemPinning` 临时改回 null 时两条用例都失败。
全量 `flutter test` 23 项通过，`flutter analyze` 干净。

**顺带记**：`_sliverTopForPixels`、`_pinchTargetScale` 那套"目标只在方向确定后求解"的修复
（10-30 日志）已生效，本次日志里 `corr=0.0`、`px` 跟手，滚动补偿本身没问题。
